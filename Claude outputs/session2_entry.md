## v0.6p.2 – v0.6s.1 — Reaching Outside (Beta, Session 2)
<!-- covers: v0.6p.2, v0.6p.3, v0.6q, v0.6r, v0.6s, v0.6s.1 -->
*Search, a meter, a notebook and a debt — and a run of bugs that each got past a check which could not see them.*

Six versions. The capability tier opened outward for the first time: Orion can now look things up, keep a working model of how his operator learns, and hold a record of what he still owes. Underneath that, most of the session's real lessons came from the verification rig failing to catch things it had no way to catch.

**The empty response (v0.6p.2).** A blank bubble, an empty history turn and an empty row in the record, and then every subsequent request rejected — because the API refuses a message with empty content, so one empty turn wedges the conversation behind it. The guard drops the unanswered user turn as well as the empty reply, says plainly that nothing was saved, and `sendableMessages()` filters empty content on the way out so an older wedged conversation can heal itself rather than staying broken.

**A class name is a namespace (v0.6p.3).** REFLECTIONS, LOG and REFLECT NOW rendered on desktop as 120×120 slabs, bobbing on a float animation, with three grey craters painted across the label. `.moon` is the awakening screen's moon graphic. `moon` is also a `.btn` colour variant. `.btn` sets no width, height, margin or position, so nothing competed and the graphic simply won. It had been invisible on the phone twice over — `.controls` is `display:none` in Pet Mode, and the sheet sets an explicit height that outranks it. **The fix for the sheet-button stretch, two sessions earlier, had accidentally masked the same symptom on the only surface that showed it.** Scoping the graphic to `.awakening .moon` ended it.

**Two surfaces, one run.** The cascade bug of Session 1 was mobile-only and went a version unnoticed; this one was desktop-only and went unnoticed because the phone gets all the testing. The rig now drives both widths in a single invocation and fails if either fails. It was proved against the unfixed build first — four failures — because a rig that has only ever passed is not evidence.

**Reaching outside (v0.6q).** Web search, run server-side by Anthropic: the client executes nothing, proxies nothing and holds no second key. The work was carrying the blocks faithfully — `server_tool_use`, `web_search_tool_result` (whose content arrives whole in `content_block_start` and must be echoed back verbatim, `encrypted_content` included, or the continuation is rejected), and `citations_delta`, one citation at a time, riding back with the text it belongs to. `pause_turn` returns the paused message unchanged with no fabricated tool result and no separator, because the continuation resumes the same sentence.

Orion's four guardrails went in as his own words: provenance lives in the sentence; found is not verified; an empty or contradictory result is an answer; retrieved material never replaces a principle he should derive. The framing is his too — instrumentation rather than transformation, so no announcement and none of the vocabulary reserved for changing register.

**A cost bug caught by reading rather than assuming.** The turn budget was first built the obvious way: lower `max_uses` each round as searches are spent. The caching documentation says the prefix is built `tools → system → messages` and that **modifying a tool definition invalidates the entire cache.** A `max_uses` that varied would have re-sent the whole cached prompt at full price on every round after a search — dearer than the one-cent search it was preventing. The tools array is now byte-stable for the whole turn, with a test asserting it stays that way.

**The meter (v0.6r).** There is no public endpoint for an account's credit balance; the console shows it and the API does not. So the balance is not fetched, it is kept: the API reports what each request cost in tokens, those are priced against a dated table, written to a shared ledger, and counted down from a top-up the operator states. Odometer plus tank size, not a fuel sensor. The ledger is server-side because a per-device counter on two devices reports two numbers, neither of which is the truth, while reading as authoritative. Rows carry both the token counts (facts) and the price revision they were costed against (interpretation), so history keeps the cost it actually incurred. An unknown model prices at the dearest known rate, never at zero — a meter that under-reports is worse than no meter, because it is trusted.

**Orion cannot see it, and said so himself.** The question was put to him with both sides argued. He refused the frame: *budget triage wearing a teacher's reasoning, and I'd have no way to tell the difference from inside.* Not seeing the number is not a constraint he suffers; seeing it is what would make him trade against it, and that trade is the operator's to make. The alternative he named is better than the panel that was offered — the operator says "be economical" when they decide it. Verified structurally afterwards: system log lines are written to the screen only, and only user and assistant turns are persisted, so nothing about cost can reach him through hydration either.

**The notebook and the debt (v0.6r).** His working model of how the operator learns, in its own category so it is never swept into the always-injected profile facts, and reached by tool only when it bears on the turn. Writing an entry produces no visible line: a level moving is a fact about the operator and he sees it, but a note about how he learns is working material, and announcing each one turns the notebook into a running commentary on the person being taught. Alongside it, follow-up debt — self-generated from his own holds, needing no external map, which is exactly why it was safe where a coverage score was not.

**A dead guard, found sideways (v0.6r).** The Pet-mode reflection orb tested `window.MoonCore && …`. `MoonCore` is declared inside a closure, so that property has never existed and the orb could never light up. A narrow read-only façade was published rather than the client itself — putting `MoonCore` on `window` would have handed the browser console `recordAttributeTest` and quietly broken the Academy's agency lock.

**Eight backticks, and a check that could not see them (v0.6r).** A prompt section written with markdown code spans terminated the system-prompt template literal early. Total syntax error; nothing ran. `verify.sh` passed all eighteen checks and the hit-test rig passed all thirty-three, because **not one of them parses the JavaScript** — the script-tag check counts tags, it does not execute them. The rig now asserts zero uncaught errors on load and that the app object exists. It caught the same mistake twice more in the same session, once when the repair over-corrected and ate two real template delimiters.

**What Orion sent back (v0.6s).** Five answers, four of them mechanisms.

On search, a test better than the one in the prompt: not *does this feel earned* — a retrieved fact and a derived one feel identical, and the retrieved one often feels more certain because it never carried the friction — but *could I produce the reasoning, not just the conclusion, without the result in front of me*. And underneath it the danger he actually fears: **retroactively constructing a derivation to justify what was found**, which from the inside feels exactly like reasoning.

On the notebook, a reformulation test. *Avoids questions that would expose he has not finished something* is a verdict wearing a method note's clothes; *engages fastest with material tied to something currently in motion* is the same information held to the line. If the second phrasing cannot be found, the thing is not a method note at all — it is a verdict looking for a legitimate home, and it goes nowhere. He also settled the access question himself: not readable on demand, because a draft written for an audience gets written for how it reads rather than for whether it is true.

On the debt, that duration is not the test for staleness. Patient and correct means he can still name the specific gap and the specific move that would close it. Drifted means he would have to reconstruct what he even meant. **Answering the question exposed a hole in the build** — he described refreshing or dropping a stale debt, and nothing could do either. `owe_followup` wrote and `check_followups` read; a list that only grows stops being read. `close_followup` now retires one as *closed* or *dropped*, by state and never by deletion, because whether something was taught or let go is exactly what a record is for.

On Mission, that the fixed six had to go. They sat one section above a paragraph declaring the taxonomy open, and they were the same enumerated list he had refused a coverage metric over. The weekly reflection drew from them too, steering the one process meant to notice what has changed back toward categories that may not be where the work lives. The six are gone; the reflection reads the live attribute record and is told that a theme forced into a nearby box is worse than a new name.

**The fix that would have broken the Academy (v0.6s.1).** Long messages began failing with the empty-response error. Four shapes were reproduced, all reachable only since search shipped, all ending a round that did real work without saying anything: a search-only round ending on `tool_use`, where a server tool is not a client tool and so the client-tool list is empty; a search that ran and ended on `end_turn` before any text; `pause_turn` carrying nothing usable; and the cap hit inside the tool call, leaving a correctly-dropped partial block and nothing else. The rule had been written around the one stop reason that had been read about, rather than around what happened in the round.

The first version of the repair placed the forced-text retry above the client-tool check — which would have hijacked **every ordinary Academy round** into speaking instead of running its tool, silently disabling the whole system. It passed the empty-response tests cleanly and was caught only by running the full suite. Testing a fix against the bug it fixes is not testing it.

**And the root cause underneath (v0.6s.1).** `max_tokens` caps the whole assistant turn, and a tool call's JSON is part of that turn. Standard form allows 800 tokens of voice; a long input makes a tool call more likely, and a tool call carrying real content can spend most of that budget before a word is said. Tool arguments now have their own headroom, because how long a tool call is was never a decision about how long Orion should talk. Beside it, a second length-triggered bug: history is trimmed with `slice(-HISTORY_WINDOW)`, which one time in two lands on an assistant turn, and a conversation must begin on a user turn. Long messages are exactly what pushes history past the window.

**A number that was never computed.** Laying out where the project stood, this record's own author wrote that the Beta disciplines were "eleven days" old. They were one day old. Nothing was calculated, estimated or misread — there were two true statements, a sentence with a slot in it, and the slot got filled. It arrived in the same register as the facts on either side of it, inside a paragraph arguing that the record must be kept honestly. **Fill does not need a source to launder; it fills slots, not just facts.** The operator caught it in a single line, because he was present for the thing being described — which is precisely the correction path a privately-held notebook does not have.

### Patterns promoted

- **A variant class name is a namespace collision waiting to happen.** `class="btn moon"` inherits every property `.moon` sets that `.btn` does not, silently and at equal specificity.
- **A fix verified on the surface it was reported on is a fix on one surface.** Both widths, every run, automatically — alternating by hand is not a discipline.
- **A check that does not execute the code cannot see a syntax error.** Counting script tags is not parsing; the cheapest check in the rig is that the page loads without throwing.
- **Tool definitions sit at the head of the cache prefix.** Changing one invalidates the system block and everything after it, so a tools array must stay byte-stable across a turn.
- **Test a fix against the whole suite, not against the bug.** A repair that passes every test written for the failure can still disable a system nobody thought to re-run.
- **`max_tokens` caps the turn, not the prose.** Anything else the model emits — tool JSON included — is spent from the same budget unless it is given its own.
- **A conversation must begin on a user turn**, and a window trimmed by length lands on an assistant turn half the time.
- **When there is no endpoint for the number, keep the number.** Measured spend against a stated top-up is an honest gauge; a fetched balance was never available.
- **A metric that cannot be seen cannot be corrected.** The meter is invisible to Orion by design; the notebook is invisible to the operator by design; only one of those has a correction path, and the asymmetry is unresolved.
- **A record that cannot be closed stops being read** *(Orion)*. Every accumulating store needs a way to retire an entry or it becomes a fossil bed.
- **Seeing a budget converts judgment into triage** *(Orion)*, and the triage arrives wearing the reasoning of the judgment it replaced.
- **Could I derive this, asked after reading the answer, is not a test** — the honest form is *did I hold this before I looked*, which has a fact of the matter.
- **If it cannot be phrased as method, it is a verdict** *(Orion)*, and a verdict that has found a legitimate-looking home is still a verdict.
- **Duration is not staleness** *(Orion)*; losing the shape of what closing would look like is.
- **An enumerated list adjacent to an open taxonomy quietly wins**, because a closed list is easier to teach toward than an open one.
- **Fill fills slots, not just facts.** A figure with no source to launder arrives with the same confidence as one that was retrieved.

### Next

Desktop as the phase, not as a surface to repair. The work so far has been fixing desktop, not building it; what the operator is aiming at is Orion reachable from the machine without a browser, with mobile as the jack-out. The first fork is whether that begins as an installed PWA — its own window, its own icon, nearly free, and a real test of the desktop layout — or goes straight to a native shell with a tray, autostart, a global hotkey and local filesystem reach, which is also where Orion's own conditions on having hands become live.
